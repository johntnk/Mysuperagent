# 架构与安全边界

## 组件

| 组件        | 文件                                        | 职责                                                                   |
| ----------- | ------------------------------------------- | ---------------------------------------------------------------------- |
| Worker 入口 | `src/worker.ts`                             | 飞书验签解密、事件与卡片回调分流、管理接口鉴权、定时触发               |
| 飞书适配    | `src/adapters/feishu*.ts`                   | 消息归一化、短命令解析、卡片渲染与回调、发送与幂等、截图下载           |
| 项目 Agent  | `src/coordinator.ts`                        | 每个项目一个 Durable Object：写入账本、排队分析、定时检查、派发 Outbox |
| 账本存储    | `src/storage.ts`                            | SQLite 按行存储、只写变化、日志上限、保留期清理                        |
| 领域规则    | `src/domain/*.ts`                           | 案例 / 问题 / 任务 / 指派 / 依赖 / 验收的状态机与校验                  |
| 分析轮次    | `src/workflow.ts`、`src/analysis/*`         | 构建并裁剪模型输入、调用模型、校验结构化建议、提交时再查修订           |
| 证据连接器  | `connector/`、`src/connector/*`             | 内网只读来源的出站轮询代理（可选，需按自己的系统改路径）               |
| 历史回放    | `src/replay/*`、`scripts/history-replay.ts` | 用群聊导出离线逐条评估，生成对照报告                                   |

## 业务对象

- **案例 Case**：一次实际发生的现象（原消息、证据、环境、版本）。每条需要处理的事项都有自己的案例，即使多条归到同一个任务。
- **问题 Issue**：需要解决的一类偏差，可关联多个案例和任务；它的验收与任务验收分开记录。
- **任务 Task**：交给一个人的具体交付。状态：待澄清、待接手、处理中、有阻塞、已修待测、已验收、暂缓、取消。
- **指派 Assignment**：指派、收到、接受、结束分开记录。“收到”不等于接手，接手不等于承诺日期。

## 模型能做什么，不能做什么

模型的输出是建议，程序负责校验：

- 只能从已核验的成员中选人；主负责人必须有逐字引用的原文依据，共同列名时留空。
- 只能引用输入里出现过的事项、任务和证据；任务更新必须带当前修订号，过期的分析被丢弃并自动重新分析（最多两次）。
- 不能宣布接手、交付或验收；群里的这类说法只会触发一张给本人的确认卡。
- 不能改变模式、白名单或权限；群消息和日志都按不可信数据处理。

## 存储

单个 Durable Object 的 SQLite 有单行大小上限，账本又会随消息不断增长，所以不把账本整份存成一行：

| 表                                                | 内容                                                                 |
| ------------------------------------------------- | -------------------------------------------------------------------- |
| `agent_records(collection, id, json, touched_at)` | 任务、问题、案例、事件、Outbox、运行记录、来源事项、提醒等，每条一行 |
| `agent_log(collection, seq, json)`                | 审计、模型建议、验收记录等只追加的日志，每条一行，超出上限丢最旧的   |
| `agent_meta(key, json)`                           | 标量字段和日志起点                                                   |

每次写入只比较并写回变化的行。保留期：去重用的事件 30 天，已结束的分析运行 30 天，未关联进行中任务的来源事项 90 天。定时检查（每 5 分钟）先判断有没有到期的任务，没有就不复制、也不写回账本；定时事件本身不再写入事件表。

## 外发与幂等

1. 领域层只生成“待发效果”（Outbox），记录目标、能力、预期修订和稳定的操作 ID。
2. 派发前重新做能力检查：模式、白名单、身份核验、通知开关、工作时间、每日提醒上限。
3. 发送使用由操作 ID 派生的飞书 `uuid`；发送中断或结果不明时标记为 unknown，1 小时去重窗口内自动重发，超时后进入人工核对列表，绝不盲目重发。
4. 任务修订变化或进入终态后，旧的待发消息自动作废。

## 运行模式

| 模式    | 行为                                                   |
| ------- | ------------------------------------------------------ |
| mock    | 全离线：合成数据、确定性模型替身、假消息通道           |
| observe | 真实只读接入：记录到内部账本，不发消息、不写外部工作项 |
| pilot   | 仅测试环境、白名单群和已核验成员，有限写入             |
| active  | 正式范围内运行，同样受上述检查约束                     |
