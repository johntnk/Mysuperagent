# 在群里怎么用

大多数操作点卡片就够了。卡片之外，还可以在群里用短命令，或者在任务的消息线程里用几句固定的话。

## 卡片

| 卡片         | 谁会收到                                 | 按钮 / 表单                                           |
| ------------ | ---------------------------------------- | ----------------------------------------------------- |
| 交接卡       | 任务的主负责人                           | 确认接手、只是收到、不是我负责                        |
| 交付表单     | 已接手的负责人                           | 交付物、测试入口、环境、版本（按验收要求预填）        |
| 验收表单     | 验收人                                   | 环境、版本、全量/抽样、证据链接；验收通过、验收不通过 |
| 验收标准表单 | 验收人；没有验收人时给协调人             | 期望行为、环境、版本要求、范围说明、全量/抽样         |
| 一键确认卡   | 在群里说了“我来/改好了/验收通过”的那个人 | 同上，对应的按钮                                      |

点击结果会以 toast 显示。点击者不是对应的人、卡片已过期（任务有了新修订）、或抽样结果想关闭全量任务时，都不会生效，并显示原因。

## 短命令

修订号可以省略，省略时表示“当前修订”。全角标点、中文引号都可以。

```
/agent help
/agent status TASK-00001
/agent accept TASK-00001            # 确认接手（也可写：/agent 接手 TASK-00001）
/agent ack TASK-00001               # 只记“收到”，不代表接手
/agent decline TASK-00001 原因       # 退回，协调人会重新安排
/agent due TASK-00001 2030-01-08 18:00
/agent deliver TASK-00001 产物=链接 入口=链接 环境=staging 版本=service:1.4.2
/agent qa TASK-00001 通过 范围=全量 证据=链接
/agent qa TASK-00001 不通过 范围=全量 证据=链接
/agent spec TASK-00001 期望=转三圈 环境=staging 版本=service:1.4.2 范围=原用例完整动作 验证=全量
/agent block TASK-00001 等动作资源入库
/agent unblock TASK-00001
/agent dependency TASK-00001 <依赖ID> 证据=链接 版本=1.4.2
```

协调人还可以：

```
/agent cancel TASK-00001 原因
/agent defer TASK-00001 原因
/agent resume TASK-00001 原因
/agent reassign TASK-00001 @成员 原因
```

写错格式时，Agent 会在原消息下回复原因和用法。命令前缀可在 `feishu.commandPrefix` 中修改。

## 线程里的固定说法

在 Agent 发出的任务消息线程里（或消息中带有任务号时），以下说法会被直接识别，末尾的标点和表情会被忽略：

| 谁       | 说法                                       | 效果                             |
| -------- | ------------------------------------------ | -------------------------------- |
| 主负责人 | 收到、好的、OK、了解、明白                 | 只记录已响应                     |
| 主负责人 | 我接手、我来处理、我来负责、交给我、我接了 | 确认接手当前范围                 |
| 主负责人 | 已修复、改好了、修好了、搞定了、已部署     | 记录交付，并给出交付表单补齐信息 |
| 主负责人 | 阻塞：原因 / 阻塞已解除                    | 登记或解除自己的阻塞             |
| 验收人   | 验收通过、验收未通过                       | 给出预填的验收表单               |
| 协调人   | 暂缓：原因 / 取消：原因 / 恢复：原因       | 对应的决定                       |

更长、更随意的话交给模型理解，最多换来一张一键确认卡，不会直接改变任务状态。
